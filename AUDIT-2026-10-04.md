# Latest project audit — 2026-10-04

## Confirmed remaining issues

### P2 — Biscuit calculates with zero base for unknown heroes

`web/src/pages/BiscuitPage.tsx` uses `baseAtkOf(r.id) ?? 0`, while UnitPicker still permits custom names. The latest patch makes base read-only, so the user cannot supply the missing value.

Reproduced through the latest browser build: replace the first default hero with custom name `AuditUnknown`. The existing screen attack remains 4,523. The result shows a 62% buff calculated from base 0, producing 4,523 + 0 and placing the hero third. The page presents this as an actual ranking instead of an incomplete calculation.

Recommended: exclude unknown-base heroes from definitive rankings and show a clear missing-data message, or disallow custom heroes on this calculator. Do not silently interpret missing base as zero.

### P2 — API allows longer skill queues than the UI

`api/src/index.ts` limits `parseSkills` to 10 entries, but `web/src/lib/types.ts` defines `MAX_SKILL_QUEUE = 3`.

Reproduced against the latest Worker with isolated local D1: POST a target containing four valid skill entries for an occupied slot. API returned 201 and saved all four. Imported/API-generated data can therefore produce queues the editor does not allow users to create normally.

Recommended: align the API limit with the UI, with an explicit decision about retaining or migrating existing longer queues.

These remaining issues were documented, not changed during this latest verification pass.

## Repeat locally

Requires installed dependencies in both `web` and `api`:

```powershell
npm.cmd --prefix api run typecheck
npm.cmd --prefix web run build
node scripts/audit-web.mjs
node api/tests/audit.mjs
```

The API suite starts its own disposable Worker on a dynamically assigned local port and disposes it afterward. `--serve` keeps the test runtime on port 8899 for manual browser work; it does not connect to production. A one-time SQL initialization route exists only in the test wrapper, never in the application source. The browser test build used `VITE_API_URL=http://127.0.0.1:8899` and `dist/audit`, separate from the normal build.
